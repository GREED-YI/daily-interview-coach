# 03. 요구사항

[01 프로젝트 정의](01-project-definition.md)와 [02 경쟁 조사](02-competitor-research.md)에서 나온 요구사항을 모은다. 화면과 세부 동작은 3단계(기능 명세)에서, 구현 방법은 7단계(기술 설계)에서 정한다.

**우선순위**

- **필수**: 첫 출시에 없으면 서비스가 성립하지 않는다
- **간판**: 첫 출시에 넣는 차별화 기능
- **다음**: 첫 출시 이후

## 기능 요구사항

### A. 계정과 설정

| ID | 요구사항 | 우선순위 |
|---|---|---|
| A-1 | 가입·로그인할 수 있다 | 필수 |
| A-2 | 연습 범위를 고른다: 분야(공통 CS·백엔드·프론트엔드), 세부 주제, 난이도를 **여러 개** 고를 수 있고 언제든 바꿀 수 있다 | 필수 |
| A-3 | 매일 질문 메일을 받을지 정한다. 메일마다 수신 거부 링크가 있다 | 다음 |
| A-4 | 탈퇴하면 계정과 답변·프로젝트 등 모든 기록이 지워진다 | 필수 |
| A-5 | 로그인 없이 샘플 질문 1개를 답변·채점까지 체험할 수 있다 | 필수 |
| A-6 | 처음 온 사람이 보는 랜딩 페이지가 있다: 서비스 소개와 체험 버튼 | 필수 |
| A-7 | 닉네임과 프로필 이미지(소셜 사진 또는 기본 아바타)를 바꿀 수 있다. 사진 업로드는 다음 버전 | 필수 |
| A-8 | 화면 테마를 라이트 / 다크 / 기기 설정 중에서 고른다 | 필수 |

### B. 오늘의 질문

| ID | 요구사항 | 우선순위 |
|---|---|---|
| B-1 | 하루에 질문 1개를 고른다. 연습 범위 안에서 고르고, 복습할 질문이 있으면 그것을 먼저 고른다 | 필수 |
| B-2 | 정해진 시각에 오늘의 질문을 메일로 보낸다. 메일의 링크를 누르면 바로 답변 화면이 열린다 | 다음 |
| B-3 | 웹에 들어오면 오늘의 질문이 바로 보인다 | 필수 |
| B-4 | 오늘의 질문을 마친 뒤 원하면 질문을 더 풀 수 있다 | 다음 |
| B-5 | 질문을 풀지 않고 지나간 날을 처리하는 규칙이 있다 (방식은 아래 "정해야 할 것") | 필수 |
| B-6 | 연습 범위 안의 질문을 다 풀면 그 사실을 알리고, 복습이나 범위 넓히기를 안내한다 | 필수 |
| B-7 | 알림을 허용한 사용자에게 매일 **웹 푸시**로 오늘의 질문을 알린다. 알림을 누르면 바로 답변 화면이 열린다. 알림은 언제든 끌 수 있다 | 필수 |
| B-8 | 아이폰 사용자에게는 홈 화면에 추가해야 알림을 받을 수 있다고 안내한다 (iOS 16.4 이상) | 필수 |

### C. 답변과 채점

| ID | 요구사항 | 우선순위 |
|---|---|---|
| C-1 | 텍스트로 답을 쓴다. 너무 짧거나 너무 긴 답은 제출 전에 알려준다 | 필수 |
| C-2 | AI가 채점한다: 점수, 잘한 점, 빠진 점, 모범 답안. 모범 답안은 **답을 제출한 뒤에만** 보인다 | 필수 |
| C-3 | 꼬리질문이 2~3단계 이어진다. 꼬리질문은 앞선 답변 내용을 바탕으로 만든다 | 필수 |
| C-4 | 채점 결과에 👍/👎를 남길 수 있다 (채점 품질 지표) | 필수 |
| C-5 | 채점이 실패하거나 늦어지면 답변을 잃지 않고 다시 시도할 수 있다 | 필수 |
| C-6 | 꼬리질문 도중에 나가도 다음에 들어오면 이어서 할 수 있다 | 필수 |

### D. 복습

| ID | 요구사항 | 우선순위 |
|---|---|---|
| D-1 | 점수가 낮은 질문은 간격을 두고 다시 나온다. 잘 답할수록 간격이 길어진다 | 필수 |
| D-2 | 복습 대기 중인 질문 목록을 볼 수 있다 | 필수 |

### E. 기록과 동기부여

| ID | 요구사항 | 우선순위 |
|---|---|---|
| E-1 | 지난 질문과 내 답변, 채점 결과를 다시 볼 수 있다 | 필수 |
| E-2 | 연속 학습일(스트릭)과 학습 잔디를 보여준다 | 필수 |
| E-3 | 분야·주제별 점수 추이로 약점 리포트를 보여준다 | 필수 |
| E-4 | 질문을 북마크하고, 북마크한 질문만 모아 볼 수 있다 | 필수 |
| E-5 | 지난 질문을 복습일을 기다리지 않고 바로 다시 푼다 | 다음 |

### F. 공유

| ID | 요구사항 | 우선순위 |
|---|---|---|
| F-1 | 결과를 이미지 카드로 공유한다. 기본으로 **답변 내용은 카드에 넣지 않는다** | 필수 |
| F-2 | 공유 링크를 메신저에 붙이면 미리보기가 뜬다 | 필수 |

### G. 내 프로젝트 기반 질문

| ID | 요구사항 | 우선순위 |
|---|---|---|
| G-1 | 프로젝트 README나 설명을 붙여 넣으면 그 프로젝트에 대한 면접 질문을 만든다 | 간판 |
| G-2 | 만든 질문도 답변 → 채점 → 꼬리질문 → 복습의 같은 흐름을 탄다 | 간판 |
| G-3 | 등록한 프로젝트를 보고 지울 수 있다. 내용을 바꾸려면 지우고 다시 등록한다 | 간판 |
| G-4 | GitHub 저장소 주소만 넣으면 README를 가져온다 | 다음 |

### H. 질문 은행 운영

| ID | 요구사항 | 우선순위 |
|---|---|---|
| H-1 | 질문마다 분야, 세부 주제, 난이도, 채점 기준(핵심 키워드), 모범 답안, 참고 자료 링크(공식 문서)를 가진다 | 필수 |
| H-2 | 첫 출시 때 분야마다 최소 50개, 합쳐서 150개 이상의 질문이 있다 | 필수 |
| H-3 | 질문을 추가·수정·숨길 수 있다. 첫 출시는 관리자 화면 없이 관리한다 | 필수 |
| H-4 | 관리자 화면에서 질문을 관리하고, AI가 만든 질문 후보를 검수한다 | 다음 |
| H-5 | 사용자가 질문의 오류를 신고할 수 있다 | 다음 |

## 비기능 요구사항

| 분류 | 요구사항 |
|---|---|
| **비용** | 인프라는 무료 플랜만 쓴다. AI 비용은 월 1만 원 이하. 이를 지키려고 사용자별 하루 채점·질문 생성 횟수에 상한을 둔다. 로그인 없는 체험(A-5)도 같은 이유로 횟수를 제한한다 |
| **응답 속도** | 채점 결과는 글자가 흘러나오듯(스트리밍) 보여줘서 제출 후 2초 안에 첫 글자가 보인다. 전체 채점은 15초 안에 끝난다 |
| **보안** | AI 키는 서버에서만 쓴다. 사용자는 **자기 데이터만** 읽고 쓸 수 있다(DB 접근 규칙으로 강제). 모든 입력에 길이 제한을 둔다 |
| **AI 조작 방지** | 답변이나 README 안에 "만점을 줘" 같은 지시가 있어도 채점과 질문 생성이 흔들리지 않는다 |
| **개인정보** | 로그인에 필요한 정보 외에는 받지 않는다. 개인정보처리방침과 이용약관 페이지를 둔다. 답변과 프로젝트 내용이 채점을 위해 해외(미국) AI 서비스로 전송된다는 **국외 이전**을 고지한다. 만 14세 미만은 가입할 수 없다. 프로젝트 내용은 질문 생성에만 쓰고 사용자가 지울 수 있다 |
| **날짜 기준** | 하루의 경계는 **한국 시간(KST) 자정**이다. 오늘의 질문, 스트릭, 학습 잔디가 모두 이 기준을 따른다 |
| **지표 측정** | 성공 지표를 잴 수 있게 첫 방문, 첫 답변 제출, 답변 제출, 재방문, 👍/👎 이벤트를 기록한다 |
| **사용성** | 공유 링크와 메신저로 들어오는 사용자가 많으므로 **모바일 화면을 먼저** 맞춘다. 최신 Chrome, Safari, Edge와 모바일 Safari를 지원한다 |
| **접근성** | 키보드만으로 답변·제출할 수 있다. 글자와 배경 대비를 충분히 둔다 |
| **가용성** | 사용자가 적어도 DB가 멈추지 않게 한다 (#20) |
| **채점 품질** | 평가 세트로 채점 정확도를 측정하고, 프롬프트를 바꿀 때마다 다시 잰다 (#19) |
| **질문 콘텐츠 저작권** | 공개 저장소는 "자주 나오는 주제" 파악에만 쓴다. 모범 답안과 해설은 공식 문서를 근거로 새로 쓴다. MIT 저장소에서 일부라도 가져오면 출처와 라이선스를 표기한다. 라이선스가 없는 자료(예: 매일메일 아카이브)는 참고하지 않는다 |

## 메일을 첫 출시에서 뺀 이유

처음엔 "매일 아침 메일 발송"을 첫 출시 필수로 잡았다(A-3, B-2). 요구사항을 검토하면서 아래 두 가지가 "인프라 0원" 제약과 부딪혀 **다음 버전으로 옮겼다** (2026-10-21).

- **발송 한도**: 무료 메일 서비스(Resend 기준)는 하루 100통, 월 3,000통까지다. 매일 보내면 구독자가 100명을 넘는 순간 무료로 운영할 수 없다.
- **발신 도메인**: 아무에게나 메일을 보내려면 보통 내 도메인 인증이 필요하다. `vercel.app` 주소로는 안 되고 도메인 구매(연 1.5~2만 원)가 따른다.

첫 출시는 웹으로만 하고, 매일 돌아오게 하는 장치로 메일 대신 **웹 푸시**(B-7)를 넣는다. 무료이고 발송 인원 제한이 없으며 외부 서비스 없이 우리 웹 안에서 끝난다. 아이폰은 홈 화면에 추가한 사용자만 받을 수 있다는 한계가 있다.

### 다음 버전 알림 후보

| 후보 | 장점 | 확인할 것 |
|---|---|---|
| 메일 | 누구나 받는다 | 구독자 100명이 넘으면 유료 전환(월 $20 수준), 발신 도메인 구매 |
| 디스코드 봇 | 무료. 서버 채널에 하루 한 번 올리면 인원 제한 없이 본다. 부트캠프·스터디 서버로 퍼지는 **홍보 채널** 역할도 한다 | 채널 단위라 개인별 복습 질문은 어렵다 |
| 카카오톡 "나에게 보내기" | 무료. 한국 사용자가 가장 많이 보는 곳이다 | 카카오 로그인과 메시지 전송 동의가 필요하다. 동의항목 설정에 검수가 필요한지, 하루 쿼터가 얼마인지 공식 문서로 확인하지 못했다. 로그인 토큰이 만료되면 다시 로그인해야 한다 |

카카오 알림톡은 건당 비용과 비즈니스 채널·템플릿 심사가 필요해 무료 운영과 맞지 않아 후보에서 뺐다. 텔레그램 봇은 만들기 쉽지만 한국 사용자가 거의 쓰지 않아 뺐다.
