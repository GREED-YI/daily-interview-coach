# 07. UI 디자인 방향

와이어프레임(#7)의 구조 위에 입히는 시각 기준이다. 색과 로고는 [06 브랜드](06-brand.md)를 따른다. Figma: [TailQ › 07 UI 디자인](https://www.figma.com/design/wPjTOU5FJdhdrMWOGZTHdh)

## 2026 트렌드에서 가져온 것과 버린 것

| 트렌드 | 판단 | 이유 |
|---|---|---|
| 차분한 UI (색·선·아이콘을 줄여 덜 시끄럽게) | **적용** | "시크하고 절제된" 방향과 같다 ([Linear 2026 리프레시](https://linear.app/now/behind-the-latest-design-refresh)) |
| 접근성을 처음부터 넣은 색 체계 | **적용** | 다크 모드까지 지원하므로 필수다 |
| 목적이 있는 모션 | **적용** | 기다림과 성취의 순간에만 움직인다 |
| 큰 글자 히어로 | **적용** | 랜딩 3초 규칙에 가장 효과가 크다 |
| AI 응답 스켈레톤·스트리밍 표시 | **적용** | 채점을 기다리는 화면에 쓴다 |
| 벤토 그리드 | **부분 적용** | 랜딩의 기능 소개 구역에만. 앱 화면까지 벤토로 채우면 산만하다 |
| 글래스모피즘(반투명 유리) | **랜딩에 적용, 앱은 하단 탭·모달 배경만** | 랜딩은 첫인상이 목적이라 화려해도 된다. 매일 읽고 쓰는 앱 화면은 대비가 떨어지면 안 되므로 글자는 항상 불투명한 면 위에 둔다 |
| 3D 모션 | **랜딩 첫 화면에만** | 3D 여우 꼬리 Q(Three.js)가 마우스·스크롤에 따라 천천히 회전한다. 처음 화면이 뜬 뒤 불러오고, 성능이 낮은 기기나 "동작 줄이기"에서는 정지 이미지로 대신한다 |
| 클레이·브루탈리즘 | **안 함** | 귀엽거나 거칠어서 신뢰가 중요한 채점 서비스와 맞지 않는다 |

처음엔 글래스모피즘과 3D를 모두 "안 함"으로 정했으나, 첫인상을 강하게 주고 싶다는 의견에 따라 **랜딩은 화려하게, 앱은 차분하게**로 바꿨다 (2026-10-22).

### 개발자 노트 방향

차분한 UI를 기본 컴포넌트 모양 그대로 채웠더니, 흔한 UI 라이브러리 기본값(연한 상자 + 동그라미 아이콘 경고, 아이콘 칩 카드, 같은 모서리·굵기)과 똑같아져 밋밋하고 어디서 본 화면이 됐다. 그래서 타깃(개발 취준생)에 맞춰 **코드 에디터·기술 노트 감성**을 더했다 (2026-10-22). 샘플 4곳을 먼저 만들어 비교한 뒤 정했다.

- 질문 번호(`Q.042`), 분야 태그(`backend / jpa`), 날짜, 글자 수, 순번(`01`), 숫자는 **고정폭 글꼴**로 쓴다
- 위계는 크기·굵기 대비로 만든다. 화면마다 시선이 처음 갈 곳이 하나다
- 상자 대신 구분선과 여백으로 묶는다. 아이콘 칩은 쓰지 않는다
- 경고는 상자 대신 왼쪽 주황 막대 한 줄로 쓴다
- 한도 소진·빈 화면처럼 할 게 없는 상태에만 여우 실루엣을 둔다

**랜딩은 기기 설정과 상관없이 항상 다크다.** 라이트 랜딩을 따로 두었더니 어두운 첫 화면과 밝은 아래쪽이 섞여 어중간해 보였다. 3D 유리 Q와 틸 빛은 어두운 배경에서 가장 잘 보인다. 로그인한 뒤의 앱은 기기 설정(라이트·다크)을 따른다.

| 요소 | 모양 |
|---|---|

| **질문 번호** | `Q.042 · backend / jpa`처럼 질문마다 고정폭 번호와 분야 태그를 붙인다. 질문이 보이는 모든 곳에 같은 모양으로 |
| **안내** | 왼쪽 2px 주황 막대 + 제목 한 줄 + 보조 한 줄, 배경 없음 |
| **여우** | 한도 소진·빈 목록·채점 실패 화면에만 작은 실루엣(64~96)으로 |
| **학습 잔디** | GitHub처럼 칸. 5단계 색 (라이트 `#EEF0F2 → #C3E9DA → #7DD3B4 → #2FA884 → #0E7C66`, 다크 `#1C2026 → #173D33 → #1F6B55 → #2A9E7C → #34C79A`). 휴식권 쓴 날은 빗금 칸. 단계 사이 대비가 낮아서 칸마다 날짜·점수 툴팁과 합계 숫자를 같이 보여준다 |
| **점수** | 큰 고정폭 숫자 + 얇은 링 하나 (막대도 시험했으나 링이 점수로 한눈에 읽혀서 링을 유지했다). 잘한 점은 강조색, 보완할 점은 주황. 빨강·초록 이분법은 쓰지 않는다 |
| **숙련도** | 점 5개(●●○○○), 채운 점은 강조색 |
| **채점 대기** | 스피너 대신 결과 자리에 스켈레톤과 "채점하고 있어요" |

## 모션

- 길이 150~250ms, 가속 곡선 `cubic-bezier(0.2, 0, 0, 1)`
- **움직이는 곳**

| 순간 | 효과 |
|---|---|
| 채점 대기 | 결과 자리에 스켈레톤 + "채점하고 있어요" |
| 채점 결과 | 점수가 0에서 올라가는 숫자와 함께 **링이 차오른다**(0.6초 한 번). 잘한 점·보완할 점은 **한 줄씩** 나타난다 |
| 꼬리질문 직전 | **면접관이 입력 중인 점 세 개(…)** 약 1초 뒤 꼬리질문이 나타난다. "AI가 되묻는" 순간을 보여준다 |
| 꼬리질문 목록 | 차례로 나타나기 |
| 꼬리잇기 | 숫자 +1 |
| 복습을 잘 풀었을 때 | 숙련도 점 하나가 채워진다 |
| 잔디 | 오늘 칸이 채워진다 |
| 버튼 | 누를 때 98%로 살짝 작아진다 |
| 토스트·모달 | 0.2초 동안 부드럽게 나타난다 |
| 랜딩 (PC) 첫 화면 | 가운데 아래 "아래로 내려 둘러보기"의 화살표가 천천히 아래로 튕긴다. 한 번 스크롤하면 멈춘다 |
| 랜딩 (PC) | 구역이 아래에서 올라오며 나타나고, 단계 구역은 스크롤에 따라 바뀐다. 3D Q는 마우스·스크롤에 따라 돈다 |

- **움직이지 않는 곳**: 탭 전환, 페이지 이동, 목록, 본문 스크롤, 패럴랙스, 컨페티, 계속 움직이는 배경. 매일 쓰는 화면이라 금방 피곤하고 느려 보인다. 랜딩 카드에 마우스를 따라오는 빛도 검토했으나 넣지 않았다
- 사용자가 기기에서 "동작 줄이기"를 켜면 모두 끈다
- CSS와 Framer Motion(무료)으로 만든다

## 상호작용 상태

| 상태 | 기기 | 모양 |
|---|---|---|
| 호버 | PC | **랜딩 카드·분야 선택 카드는 반전**(라이트는 검은 바탕에 흰 글씨, 다크는 반대). **앱 안의 카드·목록 행은 은은하게**: 면색 한 단계 진하게 + 화살표 4px 오른쪽. 버튼은 색 한 단계 진하게 |
| 누름 | 폰 | 손가락으로 누르는 순간 면색 한 단계 진하게 (폰에는 호버가 없다) |
| 포커스 | 키보드 | 강조색 2px 바깥 테두리 (Tab으로 이동할 때만 보인다) |

### 버튼

- **한 화면 안에서 같은 줄·같은 묶음의 버튼은 크기가 같다.** 주 버튼과 보조 버튼이 나란히 있으면 폭도 같게 한다. 글자만 있는 링크처럼 보이는 선택지는 쓰지 않고 버튼으로 통일한다
- PC 정렬: 가운데 한 열로 진행하는 화면(체험 결과, 공유, 로그인, 온보딩)은 버튼도 가운데. 왼쪽 정렬 내용 아래(세션, 폼)는 오른쪽 정렬. 모바일은 아래에 꽉 찬 폭
- **소셜 로그인 버튼은 각 서비스의 대표 아이콘과 색**을 쓴다(각 사의 로그인 버튼 가이드를 따른다). 카카오는 노란 바탕(`#FEE500`)에 검은 글씨, Google은 흰 바탕에 회색 테두리와 색깔 G, GitHub는 검은 바탕(`#24292F`)에 흰 글씨. 브랜드 색이라 다크 모드에서도 바뀌지 않는다(다크에서 GitHub 버튼은 테두리로 구분)

랜딩은 화려하게, 앱은 차분하게라는 방향에 맞춰 호버도 나눴다. 앱 목록까지 반전시키면 마우스를 움직일 때마다 번쩍거려 보인다.

## PC 레이아웃 (모든 화면)

| 너비 | 구조 |
|---|---|
| 모바일 (~767px) | 하단 탭 5개, 한 열 |
| 태블릿 (768~1023px) | 하단 탭, 내용 최대 너비 640 가운데 |
| PC (1024px~) | **왼쪽 사이드 메뉴**(홈·복습·기록·프로젝트·MY)로 바꾼다. 세션·문서처럼 읽고 쓰는 화면은 내용 최대 720 가운데, 홈·기록·리포트처럼 훑어보는 화면은 2열 |

- 랜딩은 PC와 모바일의 느낌을 다르게 한다. 모바일은 짧게 쌓고, PC는 **스크롤 따라 읽히는 구성**이다: 화면을 채우는 큰 제목 사이에 3D Q → 채점 화면이 고정되고 `01 질문 → 04 꼬리질문` 단계가 지나가는 구역 → 큰 문장 한 줄 → 실제 앱 화면을 브라우저 틀에 넣어 보여주기 → 바로 체험. 처음엔 첫 화면 좌우 분할(왼쪽 제목, 오른쪽 목업)이었으나 모바일과 느낌이 같고 밋밋해서 바꿨다 (2026-10-23)
- 3D Q는 **Three.js(`@react-three/fiber`)로 직접 만든다.** 여우 꼬리 Q 심볼(SVG)에 두께를 주고 유리 재질을 입힌다. 처음엔 Spline으로 정했으나 무료 플랜은 웹에 넣으면 Spline 로고가 붙고 로고를 빼려면 월 $12~15가 들어서, 무료 오픈소스로 바꿨다 (2026-10-23). 개발할 때 지금 정지 이미지(Gemini 생성)와 비교해서 실시간 3D가 더 못하면 정지 이미지 + 마우스 따라 기울기로 간다. 첫 화면이 뜬 뒤 불러오고, 모바일과 "동작 줄이기"에서는 정지 이미지로 대신한다
- 모달은 PC·태블릿에서 가운데 480 너비, 토스트는 PC에서 오른쪽 아래.
- 세션 화면은 PC에서 사이드 메뉴를 숨기고, 상단에 나가기·진행 표시(`01 답변 · 02 채점 · 03 꼬리질문 · 04 종합`)·북마크만 둔다.
- 기록은 PC에서 2열이다. 왼쪽 목록에서 행을 누르면 오른쪽에 그 기록의 요약(질문, 채점)이 뜨고, "기록 상세 보기"로 상세 화면에 간다. 모바일은 행을 누르면 바로 상세 화면으로 간다.
- 홈은 PC·태블릿에서 아래쪽에 "복습할 질문"과 "최근 기록" 미리보기를 더한다. 넓은 화면의 빈 곳을 이미 있는 정보로 채운다.

### Figma 구성

페이지 "07 UI 디자인"에 UI 킷, 모바일 3구역, PC·태블릿 3구역(처음 온 사람 / 홈·세션·모달 / 복습·기록·프로젝트·MY)과 샘플이 있다. 화면 이름은 `M/`·`Tablet/`·`PC/` + 화면 번호(S01~S34)이고, 다크는 이름 끝에 `(Dark)`가 붙는다.

### iOS 대응

Figma 모바일 프레임(390×844)은 **브라우저가 그리는 영역**을 기준으로 그렸다. 상태바와 Safari 주소창은 브라우저가 차지하므로 화면에 그리지 않았다.

| 경우 | 처리 |
|---|---|
| Safari에서 볼 때 | 상태바·주소창은 Safari가 관리해서 상단이 가려지지 않는다. 주소창이 접혔다 펴지며 높이가 바뀌므로 전체 높이는 `100vh` 대신 `100dvh` |
| 홈 화면에 추가한 앱으로 볼 때 (웹 푸시는 이 경우에만 된다) | `viewport-fit=cover`를 쓰고 상단바에 `env(safe-area-inset-top)`, 하단 탭과 아래 고정 버튼에 `env(safe-area-inset-bottom)`만큼 여백을 더한다. 다이내믹 아일랜드와 홈 인디케이터에 겹치지 않게 한다 |
| 입력칸 | 글자 크기 16 이상. 16보다 작으면 iOS가 입력할 때 화면을 확대한다 |

## 따라 할 참고

- 결과 화면: 토스 송금 완료처럼 큰 숫자 하나, 한 줄 문장, 다음 행동 하나
- 잔디: GitHub 기여 그래프와 [색약 테마](https://github.blog/changelog/2021-09-29-colorblind-themes-beta/)
- 꼬리잇기·휴식권: [Duolingo](https://blog.duolingo.com/how-duolingo-streak-builds-habit)의 원리(휴식권은 여유, 이정표 축하)만 가져오고 캐릭터와 죄책감 주는 알림은 빼기
- 목록·기록: Linear처럼 옅은 구분선과 낮춘 장식

## 피하는 것

1. 이모지·컨페티 남발, 귀여운 표현
2. 앱 화면(랜딩 제외)의 유리 효과와 3D, 유리 위에 바로 올린 글자
3. 순검정 배경에 쨍한 색을 올린 다크 모드
4. 화면마다 카드를 깔거나 카드 안에 카드
5. 꼬리잇기를 잃는다는 공포를 앞세운 문구
6. UI 라이브러리 기본 모양 그대로 쓰기 (연한 상자 + 동그라미 아이콘 경고, 아이콘 칩 + 제목 + 회색 두 줄 카드)
