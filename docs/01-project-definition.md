# 01. 프로젝트 정의

이후 모든 결정의 기준이 되는 문서다. 기능을 넣을지 말지 헷갈리면 여기의 **문제**와 **타깃**에 닿는지 본다.

## 한 줄 정의

**매일 한 문제, 면접관처럼 채점하고 되묻는 기술면접 연습 서비스.**

## 서비스 이름: TailQ (테일큐)

**Tail** Question, 꼬리질문. 이 서비스가 질문 모음과 가장 크게 다른 점을 이름에 그대로 담았다.

| 기준 | 판단 |
|---|---|
| 뜻 전달 | 이름만 봐도 "꼬리질문 서비스"인 게 보인다 |
| 이름 = 주소 | `tailq.dev`, `tailq.app`, `tailq.vercel.app`을 이름 그대로 쓸 수 있다 (2026-10 확인) |
| 검색 | "테일큐"로 검색하면 우리만 나온다. 친구가 말로 추천해도 그대로 찾아올 수 있다 |

마지막까지 비교한 후보는 **Depth**(뎁스)였다. 더 미니멀하고 고급스럽고 확장성도 넓지만, 일반 단어라 검색에 묻히고 같은 이름의 주소를 쓸 수 없어 `depthq`처럼 이름과 주소가 어긋난다. "다른 사람들이 자주 쓰는 서비스"가 목표라서 찾기 쉽고 기억에 남는 쪽을 골랐다.

그 밖에 검토한 방향: 직관형(하루면접, 데일리큐), 말장난형(꼬꼬질, 오답, 명답), 고전 인용형(문답, Elenko, Viva). 같은 이름의 서비스가 있거나 주소가 막힌 후보는 제외했다.

## 해결할 문제

| 문제 | 지금은 어떻게 하나 | 왜 부족한가 |
|---|---|---|
| 질문 목록을 **읽기만** 한다 | GitHub 면접 질문 모음, 블로그 정리 글 | 읽으면 아는 것 같지만, 내 말로 설명하려 하면 막힌다 |
| 내 답이 맞는지 **알려줄 사람이 없다** | 스터디, 지인 | 시간 맞추기가 어렵고 매일 할 수 없다 |
| 실제 면접은 **꼬리질문**으로 깊이를 본다 | 없음 | 질문 모음은 첫 질문까지만 연습시킨다 |
| 몰아서 보고 **금방 잊는다** | 시험 직전 벼락치기 | 다시 볼 주기가 없다 |

## 타깃 사용자

- **주 타깃**: 프론트엔드·백엔드 개발 직무 취업을 준비하는 부트캠프 수강생, 비전공 신입 준비생
- **부 타깃**: 이직을 준비하는 1~3년차 주니어 개발자
- **첫 사용자**: 같은 과정 동기들. 직접 써보게 하고 피드백을 받을 수 있는 사람들이다

질문 분야는 **프론트엔드와 백엔드 둘 다** 다룬다. 사용자는 연습하고 싶은 범위를 **여러 개 골라서** 정한다. 예를 들어 "공통 CS + 백엔드 중 Spring, JPA만"처럼 분야와 세부 주제를 자유롭게 조합하고, 난이도도 여러 개를 고를 수 있다. 고른 범위는 언제든 바꿀 수 있다.

| 분야 | 예시 주제 |
|---|---|
| 공통 CS | 자료구조, 네트워크, 운영체제, 데이터베이스 |
| 백엔드 | Java, Spring, JPA, 트랜잭션, 인증, 설계 |
| 프론트엔드 | JavaScript, TypeScript, React, 브라우저 렌더링, 웹 성능 |

## 핵심 경험

1. 매일 아침 **이메일로** 오늘의 질문 1개가 온다 (5분이면 끝나는 양)
2. **내 말로** 답을 쓴다
3. AI가 채점한다: 점수, 잘한 점, 빠진 점, 모범 답안
4. 실제 면접처럼 **꼬리질문이 2~3번** 이어진다
5. 부족했던 질문은 며칠 뒤 **다시** 나온다 (간격 반복)
6. 연속 학습일(스트릭)과 분야별 약점 리포트로 내 실력 변화를 본다

## 출시 범위

### 첫 출시

| 기능 | 왜 필요한가 |
|---|---|
| 연습 범위 설정 (분야·세부 주제·난이도 복수 선택) | 관심 없는 분야 질문이 오면 바로 떠난다. 사람마다 준비하는 범위가 달라서 하나만 고르게 하면 맞지 않는다 |
| 오늘의 질문, 답변, AI 채점 | 서비스의 중심 |
| 꼬리질문 2~3단계 | 실제 면접은 깊이를 본다. 질문 모음과 가장 크게 다른 점 |
| 간격 반복 복습 | 부족한 질문을 다시 만나야 실력이 된다 |
| 매일 아침 이메일 발송 | "데일리" 서비스다. 사용자가 기억해서 들어오기를 기다리지 않는다 |
| 스트릭·학습 잔디 | 습관을 만드는 가장 가벼운 장치 |
| 분야별 약점 리포트 | "내가 뭐가 약한지" 보여주면 계속 쓸 이유가 생긴다 |
| 결과 공유 카드 | 공유가 곧 홍보다 |
| 로그인, 학습 기록 | 위 기능의 기반 |

### 간판 기능: 내 프로젝트 기반 질문

내 프로젝트의 README나 설명을 넣으면, 그 프로젝트에 대해 면접관이 물을 법한 질문을 만들어 같은 방식(답변 → 채점 → 꼬리질문)으로 연습한다.

실제 면접의 절반은 "이 프로젝트에서 왜 이렇게 했나요?"다. 질문 모음 서비스는 이걸 연습시켜 줄 수 없다. **다른 서비스와 가장 크게 다른 점**이다.

### 다음 버전

- 채용공고 맞춤 질문: 공고를 넣으면 그 회사에 맞춘 질문 세트
- AI 질문 생성과 관리자 검수: 질문 은행을 계속 늘리는 장치

## 성공 지표

출시 후 4주 동안 본다. 숫자는 **가설**이고, 실제 데이터를 보고 고친다.

| 지표 | 목표 | 왜 이 지표인가 |
|---|---|---|
| **주간 답변 제출 수** (북극성 지표) | 꾸준히 증가 | 방문이 아니라 "연습을 했는지"가 이 서비스의 가치다 |
| 첫 방문자 중 첫 답변까지 간 비율 | 50% 이상 | 첫 경험에서 이탈하면 이후 지표가 의미 없다 |
| 7일 재방문율 (D7) | 20% 이상 | "매일 오는 서비스"가 목표다 |
| 채점 피드백 만족도 (👍 비율) | 70% 이상 | 채점이 엉터리면 아무도 다시 오지 않는다 |
| 월 운영비 | 인프라 0원, AI 비용 1만 원 이하 | 무료 운영이 전제 조건이다 |

## 하지 않을 것

| 하지 않을 것 | 이유 |
|---|---|
| 음성 답변, 실시간 모의면접 | 음성 인식 비용과 복잡도가 크다. 텍스트로 가치를 먼저 검증한다 |
| 알고리즘 코딩 테스트 | 프로그래머스, 백준이 이미 잘한다. 우리는 "설명하는 능력"에 집중한다 |
| 커뮤니티, 랭킹 | 사용자가 모인 다음 이야기다 |
| 모바일 앱 | 반응형 웹으로 충분하다 |
| 유료 결제 | 가치를 검증하기 전에 돈을 받지 않는다 |

## 제약

- **운영비**: 인프라는 무료 플랜만 쓴다 (Vercel Hobby, Supabase Free). 돈이 드는 건 AI 채점(Claude API)뿐이다
- **개발 인원**: 1명
- **일정**: 정해진 마감 없이 진행한다. 대신 단계(마일스톤) 순서는 지킨다
